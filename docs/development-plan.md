# 開発計画

作成日：2026-09-12。現在地：P-SPECの仕様策定・机上確認を完了、一括レビュー待ち。実装・プレイテストは未着手。

## 合意した開発順序

**詳細仕様を作成 → テキスト版PoC → ビジュアル化 → バリエーション追加**の順に進める。最初から0〜20歳の育児と老後・最期までを扱い、イベント・初期条件・進路などの種類を少数に絞ってPoCを作る。

案2のコメディと、ボードゲーム的な偶然を楽しむ方針を採用済み。育児編は半年単位・全40ターンで確定済み。子どもはまず1人。少数のシンプルなパターンで、パラメータとイベントがどうつながり、選択が長期的な幸福にどう影響するかを確認する。将来の全バリエーションを先に定義する必要はないが、PoCに使うパターンは最期まで仕様をつなぐ。

工数は仕様と技術構成が決まった後に見積もる。段階は検証結果と完了条件で管理する。旧P0〜P4からの変更は意思決定記録D-005に残し、現行段階には意味が分かるIDを使用する。

## P-SPEC：基本パターンと詳細仕様を作る

目的：人生全体を通すテキスト版を実装可能な状態にする。

SPEC 1.0と分冊に詳細仕様を作成済み。ユーザーの委任に基づく採用設計と、調整仮値を区別している。

P-SPEC内の順序、各ステップで決めること、進め方、成果物、完了条件、進捗は[仕様策定計画](specification-plan.md)を正本とする。SP-01〜09の成果と根拠は仕様策定計画を参照する。仕様番号順や未決事項番号順に決めるのではなく、依存関係に沿って進める。

成果物：パラメータ定義、イベント定義、接続条件、基本パターン、老後と評価、CLI契約、受け入れ条件とテストプレイ手順を備えた初版SPEC。

完了条件：SP-09の最終点検を満たし、少数の基本パターンが最期までつながり、追加のゲームルールを推測せずにCLIを実装できる状態である。詳細な進捗はこの文書に重複記載せず、仕様策定計画で更新する。

## P-TEXT：テキストベースのPoCを作る

目的：ビジュアルなしで、選択・変化・人生の振り返りがゲームとして成立するかを確認する。

範囲：子ども1人、0〜20歳の半年単位・全40ターンの進行、少数の基本パターンとイベント、家計・時間・ストレス・親子関係・子どもの状態、簡単な進路、老後の自動進行、最終評価と履歴、AIエージェントが操作できるCLI。SPEC S-001〜S-012が対象。

CLIを採用し、人向けのテキストとエージェント向けの構造化出力で操作できるようにする。具体的な契約はSPEC S-011で管理する。グラフィック、イラスト、アニメーションはこの段階に含めない。

後に回すもの：大量のイベント、詳細な職業や祖父母のバリエーション、複数の子ども、深刻な事件の多様な分岐、製品向けの演出・配布機能。

成果物：最初から最期まで遊べるCLI、操作方法、再現用の条件・操作記録、AIエージェントのテストプレイ記録と検証結果。

完了条件：

- 定義した基本パターンすべてで、育児から老後・最終評価まで通せる。
- AIエージェントが非対話のCLI操作と公開情報だけで完走でき、JSONの解析や選択肢の取得で表示文の推測に依存しない。
- 中断・再開と操作ログの再生で結果が一致し、無効入力や再送でターンや効果を二重適用しない。
- イベントがないターンも進行し、年代の境界と20歳での移行に欠落や二重処理がない。
- 同じ初期条件・乱数条件で異なる方針を比較でき、短期と長期の利点・負担を説明できる。
- 観察をもとに方針を変える場面と、悪化から回復する経路を確認できる。
- 最終評価が引き継いだ状態と履歴から計算され、結末の文章だけを差し替えたものになっていない。
- 異なる幸せと、社会的成功と幸福が一致しない結果を、採用した基本パターンで確認できる。
- 説明できない結果、単調さ、常に有利な方針を記録し、修正するか残す理由を明示する。

計算の整合性は必要な自動検証で確認する。AIエージェントは方針・シードを変えてテストプレイし、進行不能、偏り、説明できない結果を記録する。人による面白さや感情の評価は別に確認する。方法と比較条件はQ-007、記録の要件はSPEC S-012で定義する。

## P-VISUAL：テキスト版をビジュアル化する

目的：検証したゲームを、状態の把握と操作がしやすい画面にする。

表現はモノクロでシュール、UNDERTALEのような雰囲気という方針を採用済み。具体的な画面と描画方法はQ-012で決める。

範囲：家族の状態、今期の方針、出来事への対応、履歴、老後の振り返りを視覚的に表現する。画面や表現の仕様を先に追加し、テキスト版の計算とイベントデータを再利用する。

ビジュアル化後もCLIを残し、AIエージェントの比較と不具合の再現に使う。

完了条件：

- テキスト版と同じ初期条件・乱数条件・選択で、同じ状態と最終評価になる。
- 必要な観察と選択肢が画面から利用でき、隠しパラメータが意図せず表示されない。
- 初めから最期まで画面操作で完走できる。
- 操作量と理解しやすさを確認し、問題を修正する。

この段階でゲームルールも変更する必要が出た場合は、表示の変更と区別し、SPECと共通の計算処理を更新して両方で確認する。

## P-EXPAND：バリエーションを徐々に増やす

範囲：イベント、子どもの個人差、家庭条件、仕事、祖父母の支援、進路、関係修復、結末を少しずつ増やす。複数の子どもも、この段階以降に独立した拡張として扱う。

追加ごとに、仕様 → 共通の計算・データ → テキストで再現・比較 → ビジュアルへの反映 → 検証、を行う。

各追加の完了条件：

- 発生条件、状態変化、後続イベントや評価への接続を説明できる。
- 単に文章が違うだけでなく、観察や判断に新しい意味がある。
- 既存の基本パターンを再確認し、意図しない結果の変化がない。意図した変更は理由を残す。
- 人生全体を引き続き完走できる。

## P-RELEASE：製品として整える

バリエーション追加の後に、保存と互換性、難易度、対応環境、配布に必要な品質を整える。詳細は対象環境と提供範囲が決まってから仕様化する。

完了条件：対応環境で一通り遊べ、保存・再開で進行が壊れず、採用した人数・イベント量でも操作が過大にならない。
