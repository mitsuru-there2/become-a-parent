## 合意した開発順序

**詳細仕様を作成 → CLIで実装・検証 → 必要なUI・ビジュアルを追加**を、今後のゲーム開発・機能拡張でも繰り返す（D-021）。GUIはCLIのインターフェースとして扱う。全体の段階はテキスト版PoC → 操作GUI → 画像・演出 → バリエーション追加。最初から0〜20歳の育児と老後・最期までを扱い、イベント・初期条件・進路などの種類を少数に絞ってPoCを作る。

案2のコメディと、ボードゲーム的な偶然を楽しむ方針を採用済み。育児編は半年単位・全40ターンで確定済み。子どもはまず1人。少数のシンプルなパターンで、パラメータとイベントがどうつながり、選択が長期的な幸福にどう影響するかを確認する。将来の全バリエーションを先に定義する必要はないが、PoCに使うパターンは最期まで仕様をつなぐ。

工数は仕様と技術構成が決まった後に見積もる。段階は検証結果と完了条件で管理する。旧P0〜P4からの変更は意思決定記録D-005に残し、現行段階には意味が分かるIDを使用する。

## P-TEXT：テキストベースのPoCを作る

目的：ビジュアルなしで、選択・変化・人生の振り返りがゲームとして成立するかを確認する。

範囲：子ども1人、0〜20歳の半年単位・全40ターンの進行、少数の基本パターンとイベント、家計・時間・ストレス・親子関係・子どもの状態、簡単な進路、老後の自動進行、最終評価と履歴、AIエージェントが操作できるCLI。SPEC S-001〜S-012が対象。

CLIを採用し、人向けのテキストとエージェント向けの構造化出力で操作できるようにする。具体的な契約はSPEC S-011で管理する。グラフィック、イラスト、アニメーションはこの段階に含めない。

後に回すもの：大量のイベント、詳細な職業や祖父母のバリエーション、複数の子ども、深刻な事件の多様な分岐、製品向けの演出・配布機能。

成果物：最初から最期まで遊べるCLI、操作方法、再現用の条件・操作記録、AIエージェントのテストプレイ記録と検証結果。

完了条件：

- 定義した基本パターンすべてで、育児から老後・最終評価まで通せる。
- AIエージェントが非対話のCLI操作と公開情報だけで完走でき、JSONの解析や選択肢の取得で表示文の推測に依存しない。
- 中断・再開と操作ログの再生で結果が一致し、無効入力や再送でターンや効果を二重適用しない。
- イベントがないターンも進行し、年代の境界と20歳での移行に欠落や二重処理がない。
- 同じ初期条件・乱数条件で異なる方針を比較でき、短期と長期の利点・負担を説明できる。
- 観察をもとに方針を変える場面と、悪化から回復する経路を確認できる。
- 最終評価が引き継いだ状態と履歴から計算され、結末の文章だけを差し替えたものになっていない。
- 異なる幸せと、社会的成功と幸福が一致しない結果を、採用した基本パターンで確認できる。
- 説明できない結果、単調さ、常に有利な方針を記録し、修正するか残す理由を明示する。

計算の整合性は必要な自動検証で確認する。AIエージェントは方針・シードを変えてテストプレイし、進行不能、偏り、説明できない結果を記録する。人による面白さや感情の評価は別に確認する。方法と比較条件はQ-007、記録の要件はSPEC S-012で定義する。
