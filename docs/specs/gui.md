# S-013：共通の公開操作に対するGUI

2026-09-15。D-023・D-027によりReact / TanStack StartのSPAモードへ更新。ゲームと保存の仕様は[S-011](cli.md)、移植の条件は[S-014](web.md)。実装は[React画面](../../src/components/game/screens.tsx)と[公開状態ストア](../../src/stores/game.ts)。

## 画面と境界

- `/` は正式HERO、新規開始（家庭・シード）、保存一覧、ファイル取り込み。
- `/play/$runId` は育児の進行、履歴、遊び方、終了後の結末。直リンク・再読込でも同じ保存を開く。
- 家族・観察・選択肢・予測は共通サービスの公開応答。隠し状態をゲーム画面へ渡さない。情景文は公開の年代・季節のみで選ぶ。
- 各親の仕事・世話・関わり・休息・自分の時間、活動・強度・担当・関わり方・支援を編集できる。値域は共通のactionsから取得。
- 4つの方針プリセット、世話配分補助、無理のない案、前期の方針への復帰を提供。未保存の編集は確定を無効にし、保存または取消が必要。ブラウザを閉じる際に未保存なら警告する。
- 選択肢は回答として保存し、確定までは変更できる。費用・入金・配分調整の必要性を表示する。
- 確定はforecast.can_advanceに従い、未回答・資源不足では無効。処理中は更新を無効にし、保存成功・失敗を表示する。競合時は編集を取り消して最新保存を読み直せる。
- 直前の半年、全期間の収支・観察・操作、老後の節目、親別の5軸、子の幸福・主体性・社会的成果と5結末を表示する。
- 書き出し・取り込みはサービスの交換形式を利用し、同IDの上書きをしない。通常UIはdebug-stateを呼ばない。
- 狭い画面は縦並び。ラベル、キーボードフォーカス、減らした動きへの対応を備える。UI用のMotionはゲーム結果に影響しない。

## 受け入れ条件

AC-013-A：画面だけで新規→回答→編集→確定→40期→成人後→結末→全履歴まで到達。

AC-013-B：GUIの保存をCLIへ書き出し・取り込みし、同じサービスの再生で一致。

AC-013-C：未保存案・未回答・資源不足・処理中では確定不能。競合・保存失敗の理由と復旧方法が分かる。

AC-013-D：画面は公開応答だけを利用。保存の書き出しは明示操作として全状態を含む。ローカルHTTPのHost/Origin/セッショントークン検査はサーバー削除により対象外。

AC-013-E：デスクトップと狭い画面で文字・選択・操作が読める。正式HEROと情景文はゲーム計算から分離する。

## フォーム状態と購読（D-026）

- 新規開始・方針編集・保存ファイル取り込みはTanStack Formで入力値・検証・送信状態を管理する。新設・改修するフォームも原則同様とする。
- 各入力は`form.Field`、説明や送信状態は必要な値に限定した`form.Subscribe`で購読する。フォーム全体の入力値を親画面やNano Storesへ複製しない。画面外の離脱・進行ガードには未保存の真偽値のみ共有する。
- 入力の構造検査には既存Valibotスキーマを利用できる。資源制約・進行・保存の最終検査は共通サービスを正本とする。
- 方針の未保存案はタブ変更・出来事への回答・保存失敗でも保持する。保存成功・取消・前期へ復帰・期の進行・保存の読み直しで基準値を更新する。値を保存時と同じに戻せば未保存ではなくなる。

AC-013-F：新規開始・方針編集・ファイル取り込みが従来の公開操作で動作する。関連入力の補完、プリセット、取消、二重送信防止を維持する。ある入力だけの変更で無関係な入力や親フォームを再描画しないことをコンポーネントテストで確認する（送信・未保存状態の変化等、関連する更新は除く）。
