# S-015：設定データ・難易度・追加シナリオ

状態：実装・検証済み（2026-09-15、D-024）。根拠は[設定化の検証](../playtests/2026-09-15-content.md)。数値は調整仮値であり、面白さや現実の育児の実証値ではない。

## 設定と処理の境界

JSONをゲームデータの正本とし、イベント本文・選択肢・費用・効果・発生期・条件・再発間隔・確率、仕事・年代別費用、珍事、情景・結末・画像参照を設定する。エンジンは条件評価・効果適用・収支計算・抽選・人生進行を共通処理する。新しい状態変数や計算方式の追加は仕様とエンジンの変更を要する。編集箇所・値域・効果キー・登録方法は[設定ガイド](../../config/README.md)、実装上の型は[types.ts](../../src/content/types.ts)、検査は[validation.ts](../../src/content/validation.ts)を参照する。JSON中のコードは実行しない。既存のcore/events/endingの表は初版の基準値として残し、設定版の値はJSONを参照する。

## 開始条件

`new`に省略可能な`difficulty`（easy / normal / hard、既定normal）と`packs`（パックID配列、既定空）を追加する。難易度は初期資金と毎期の基本生活費で調整する。3段階の名前・説明・数値は設定に置く。開始後の変更は認めず、公開状態で現在の難易度と追加パックを表示する。`scenarios`は家庭、難易度、利用できるパックを返す。

## 追加パック

パックはID・版・名称・前提データ版・依存パックと、追加家庭・イベント・任意行動・画像を持つ。登録済みで選択されたパックだけを合成する。未知ID、重複、依存不足・循環、版不一致、既存IDとの衝突、不正な条件・効果・確率・画像参照は開始前に拒否する。合成順はID順に固定し、既存データを上書きしない。

追加行動は`plan.extra_action`で毎期0〜1件選び、`none`で解除する。費用・担当親の時間・対象年代・効果を持ち、公開応答と`actions`から発見できる。通常の予測・入力検査・確定・履歴・再送の対象とし、利用不能な行動の持越しは確定を拒否する。追加イベントは独立した抽選スロットを使い、既存の抽選値を変えない。確率は0〜100の整数%。同一グループの条件イベントは優先順位順で最大1件。グループなしは独立発生。

設定例は開発用と明記し、本編への自動追加や販売商品としての扱いはしない。今回作るのはコンテンツ読込の境界。価格・決済・購入権利の検証と有料コンテンツ配信はQ-015の将来実装で扱う。ローカル設定の有効化は購入証明にはならない。

## 保存と再現

新規保存はrules-2 / data-2 / save-3。開始時の合成済み設定・難易度・パック版・設定ハッシュを保存し、以降の表示・計算・再生にはその設定を使う。設定ファイル更新や登録パック削除は既存保存へ波及しない。旧save-2は凍結したdata-1の設定で読み込む。乱数キーは従来の系列を保ち、追加イベントは専用スロットを使う。保存の整合性検査は購入権利や改ざん防止を保証するものではない。

## 受け入れ条件

- AC-015-A：標準・追加なしで従来の5本200期と成人後の参照値が一致する。
- AC-015-B：3難易度の初期資金・予測費用が異なり、各難易度で40期と成人後まで公開操作で完走・再生できる。不明な難易度は保存を作らない。
- AC-015-C：設定例だけで追加家庭・行動・イベントを合成できる。未選択なら現れない。費用・時間・効果・条件・確率0/100・再発間隔が適用される。
- AC-015-D：不正データ・衝突・依存不足を拒否し、無効行動、未回答、過剰配分、再送によって効果を二重適用しない。
- AC-015-E：設定変更後の再開・書き出し・取り込み・再生が一致し、旧保存も従来の設定で再生できる。
- AC-015-F：ブラウザも共通操作で難易度・追加コンテンツを選択し、公開情報から行動・画像を表示する。

## 検査ライブラリ（2026-09-15、D-025）

実装・検証済み（[検証記録](../playtests/2026-09-15-content.md#valibot導入の検証d-025)）：設定・パック・保存設定の構造検査にValibotを使い、TypeScript型はスキーマから導出する。未知キー、型違い、整数範囲違反を拒否し、文字列の数値変換や入力の補正は行わない。画像・行動IDの参照、確率合計、パック依存、設定ハッシュ等の整合性検査も維持する。エラーは既存のContentError / INVALID_CONTENT / CORRUPT_SAVEへ接続し、構造違反は可能な限り項目パスを示す。CLIの方針・選択・ID・整数入力にも同じライブラリを使い、INVALID_INPUTと入力不正時の保存不変を維持する。ゲーム規則・保存形式は変更しない。

受け入れ：既存の設定・難易度・追加パック・旧保存・再生の全テストが通り、不正な入れ子、未知キー、文字列数値、NaN、Infinity、特殊な辞書キーを拒否する。Standard Schema経由でTanStack Routerが受理・拒否を扱えることを結合テストで確認する。現在の画面では検索パラメーターを使っていないため、導入のためだけに新しいURL仕様は追加しない。

## JSON編集時の型チェック

実装・検証済み（[検証記録](../playtests/2026-09-15-content.md#json編集支援の検証)）：Valibotの設定スキーマからJSON Schemaを自動生成し、VS Code互換のJSONエディタへファイル単位で関連付ける。本編・旧保存用設定、追加パック配列、追加パック単体のサンプルを対象とする。編集時に項目・列挙値の補完と型・必須項目・未知キー・数値範囲の診断を利用できるようにする。

Valibotを正本とし、生成JSON Schemaは手で編集しない。設定本体に`$schema`を追加せず、ゲームデータ・設定ハッシュ・保存形式を維持する。生成物が古い場合は`bun run lint`・`bun run check`で検出する。JSON Schemaに変換できない独自条件やパック間参照は、引き続き`bun run check:content`で検査する。

受け入れ：生成物が再生成結果と一致し、JSON言語サービスで実際の設定に構造エラーがなく、不正な型・確率・未知キーを診断できる。対象分野などの列挙値と項目名の補完を確認する。

## コマンド・コミット時の検査

- `bun run lint`と`bun run check`は、生成JSON Schemaの同期、エディタの関連付けに対応する全JSON本体、設定の独自条件・参照・登録パック・画像の検査を含む。
- JSON本体の診断はファイル名・行・列を表示し、違反があれば非0で終了する。追加されたサンプルJSONも関連付けのglobから検出する。
- Lefthookのpre-commitは、対象のステージ済みファイルをformat・再ステージした後にlintを実行する。検査に失敗したコミットは中止する。formatの対象外は既存のVitePlus設定に従う。
- 受け入れ：正常な設定でlint・check・フックが通る。型違いのJSON、古い生成スキーマ、lint違反ではフックが失敗する。整形結果がステージされ、部分ステージの未選択変更がコミットへ混入しないことを一時リポジトリで検証する。
