# 成人後・老後・最終評価

2026-09-15追記：設定化した数値・本文・確率は[S-015](content.md)と[設定JSON](../../config/README.md)を参照する。以下の表は初版の基準値・計算方式を示す。標準設定の初版参照値との一致は維持している。


[SPEC索引](../SPEC.md)に属するS-009の規範仕様。2026-09-15に[TypeScriptへ移植](../../src/engine/adult.ts)、[既存最終値と境界の照合](../../tests/engine.test.ts)を実施。親と子の評価を分けること、親の5軸、親ごとの差を残すことは合意済み。以下の式・期間・値は委任に基づく初版設計であり、調整仮値。現実の寿命や幸福を予測するモデルではない。

## 20歳での引き継ぎ

第40ターンの全効果・遅延予約を反映した後に実行する。子どものT_A/T_B、X、U、I、B、親のS/H/F/N/G、K、家計M、最後のwork、公開履歴とrepaired/oddity_countを保持する。育児中のdraft・未回答・予約は空であることを検査。祖父母の状態は履歴として凍結し、成人後に利用しない。

親の口座 `W_A=(M+1)//2`、`W_B=M//2` に分け、家計Mを成人後の支出に重ねて使わない。親が亡くなった後の口座は凍結する。遺産・介護分担の計算は初版に含めず、子どもの近居や支出を生存条件にしない。

## 子どもの進路

1. 希望分野dはIが大きい方、同値study。親の入力では指定できない。
2. `B_d>=60` なら `specialist`（学習なら「学びを生かす専門の道」、創作なら「作ることを仕事にする道」）。それ以外でU>=50なら `explorer`（「試しながら自分の道を探す」）、それ以外は `supported`（「相談しながら足場を作る」）。進路は20歳の要約で、職業・大学・雇用制度の詳細は模擬しない。
3. `luck` はR(seed,"adult",0,"career")が0〜19なら−10、20〜79なら0、80〜99なら+10。社会的成果 `C_success=C((B_d+U)//2+luck)`。以降、成果は固定。成功が幸福と同一になる式にはしない。
4. R(seed,"adult",0,"distance")が、C_success>=60なら60未満、それ以外なら30未満のとき `far`、それ以外`near`。表示は「遠方／近くで暮らす」。遠近だけで信頼・幸福を増減しない。
5. 子どもの幸福 `J=(100-X+U+max(I_study,I_craft))//3`。Cで収める。成人後も各節目に再計算する。

結婚・孫・成人後の子どもの死亡・詳細な職歴変更は初版では模擬しない。表示しない属性を「なし」と決めつけない。高幸福の条件に含めないという合意を維持する。

## 自動進行の年表

両親の初期年齢は同じだが健康等は別々に更新し、それぞれの最期を判定する。

| k    |   親の到達年齢 |   子の到達年齢 | 区間             | お金の計算                               |
| ---- | -------------: | -------------: | ---------------- | ---------------------------------------- |
| 1〜3 |       55,60,65 |       25,30,35 | 50〜65歳の中年期 | 各親：5×(最後の半年収入×2−年間生活費240) |
| 4〜8 | 70,75,80,85,90 | 40,45,50,55,60 | 65歳以降の老後   | 各親：5×(年金200−年間生活費220)=−100     |

日々の操作は発生しない。子ども20歳からいきなり親65歳に飛ばさず、全5年区間を計算する。各区間は開始時に生きている親に一度だけ適用し、死亡は区間末の節目で判定する。区間中の正確な死亡日はモデル化しない。

## 節目の更新順と式

すべての右辺は節目開始値。まず生存親それぞれの口座に表の増減を加え、負なら不足分を「暮らしを縮小して調整」と記録して0にする。`short_p`は不足があったかのbool。上限99999。次の通常差分を同時に適用する。

```text
S_p' = C(S_p - 8 + 4*short_p)
H_p' = max(0, H_p - (5 if k<=3 else 10) - 3*[S_p>=60] - 2*short_p)
F_p' = C(F_p + (3 if N_p>=50 else -3) - 3*[H_p<30])
N_p' = C(N_p - 2)
T_p' = C(T_p + (2 if T_p>=50 else -1))
G_p' = C(G_p + [T_p<30 or F_p<25] - [T_p>=60 and F_p>=50])
X' = C(X - 5 + 5*[C_success<40])
U' = C(U + [route!=supported])
```

I・B・K・C_success・居住距離は成人後固定。親の死亡後、その親に対するTも凍結する。子どものX/Uは少なくとも一人が区間開始時に生存していれば区間ごとに一度だけ更新し、親の人数分は更新しない。

次に節目ごとの出来事をID順に適用する。選択を求めず、すべて非金銭の小さな変化と文章で示す。

| ID・時期     | 条件・表示                                                                                          | 効果                 |
| ------------ | --------------------------------------------------------------------------------------------------- | -------------------- |
| A-01・k=1    | T_p>=50なら「近況の連絡が届いた」、未満なら「連絡は用件が中心だった」。判定は通常更新後、各生存親別 | 前者F_p+2、後者効果0 |
| A-02・k=3    | N_p>=50なら「退職後にも会う人と予定がある」、未満なら「仕事の外の過ごし方を探し始めた」             | 前者F_p+3、後者効果0 |
| A-03・k=4〜8 | 各生存親にR(seed,"adult",k,"health-A/B")<20なら「体調を崩し、しばらく休んだ」                       | H_p−5、下限0         |
| A-04・k=5    | repaired=trueかつT_p>=60なら「昔の言い争いを、今は一緒に振り返れた」                                | G_p−3                |
| A-05・k=6    | oddity_count>0なら「妙な作品が、まだ家に残っている」                                                | 文章のみ             |

親ごとの生存判定は上記イベント後に行い、親の年齢65以上かつH_p=0、または年齢90で最期に達する。初期年齢が同じでも死亡期は一致させない。両親が同一期に亡くなった場合は同時として処理し、A/B順による差を作らない。

一方だけが亡くなれば、生存親のSに+10を一度加え、喪失の文を履歴に残す。亡くなった親の評価を先に保存し、この喪失の効果をその親の最期へ遡及しない。残る親は次の節目へ進む。90歳までに両親が必ず終了し、それ以上の節目は生成しない。

各節目では生存状態、実際の口座増減、健康・親の状態、子どもの進路・幸福・主体性、連絡、出来事を出す。成人後に限り、子どもの幸福J・主体性Uは振り返りの評価値として公開する。育児中の非公開X/I/B/Tや適性はここでも生値を出さない。

## 最期の幸福度

親それぞれの死亡時の状態で以下を一度計算し、以後は凍結する。同時死亡の場合は双方とも配偶者がその区間までいたとして扱う。

| 項目                | 0〜100の計算                                                                     |
| ------------------- | -------------------------------------------------------------------------------- |
| R：親密な関係       | 配偶者が前の節目までに死亡済みなら `(2*T_p+N_p)//3`、それ以外 `(2*T_p+N_p+K)//4` |
| L：生活の安心       | `(min(100,W_p//5)+H_p)//2`                                                       |
| F：親自身の充実     | F_p                                                                              |
| Q：子どもへの安心感 | `(J+C_success)//2`                                                               |
| G：後悔             | G_p。低いほど後悔が少ない                                                        |

`happiness_p=(25*R+25*L+25*F+15*Q+10*(100-G))//100`。

表示は親A・親Bそれぞれの幸福度と5軸、子どもの幸福Jと主体性Uを並べる。家族の総合点を作らず、親の幸福に子どもの不幸による上限を設けない。学歴・名声・金額そのものへの加点や、近居・結婚・孫・介護の必須条件はない。親の子どもへの安心感Qには暮らしの成果も寄与するが、親の幸福全体を支配しない。

結果ラベル：幸福75以上「満ち足りた振り返り」、45〜74「喜びと心残りのある振り返り」、44以下「心残りの大きい振り返り」。人格の優劣ではなくゲーム内の内訳の要約。子どもJは親のラベルへ混ぜない。

結果文は次を固定順に組み立てる。親の幸福・内訳 → 子どもの希望分野と進路・成果 → near/far → 子どもの幸福・主体性 → 条件を満たす思い出 → 親ごとの最期。思い出はrepairedかつT_p>=60なら修復、C_success>=70かつT_p<40なら「成果は大きかったが、会話は少なかった」、farかつT_p>=60なら「距離があっても連絡が続いた」、N_p>=60なら「家族以外とのつながりも支えになった」、oddity_count>0なら「回覧板の作品」を、それぞれ一度追加する。条件不成立の事実は書かない。

## 受け入れ条件

- AC-009-T：40期の末に予約0、子20歳・親50歳の状態から、k=1〜最大8までを欠落なく計算しfinishedになる。最終更新前の値を引き継がない。
- AC-009-D：片親65歳H=0で死亡、他方H>0なら後者だけを継続。最期の点を後から変えない。同時死亡は片方だけに喪失を加えない。Hが高くても90歳で終了。
- AC-009-S：R=80,L=60,F=70,Q=50,G=20なら幸福=68。距離、婚姻・孫の記載、oddity_countだけの変更では同点。C_successだけを+20しても、J等を固定した直接の幸福増分は最大2（床丸め込み）。
- AC-009-V：高成果・低信頼と、高成果・高信頼、低成果・高充実、遠方・高信頼の境界入力を比較する。社会的成果が高い例を一律に低幸福にしない。

## 5種類のエンディング（ending-1）

2026-09-14の依頼で追加。最終結果に必ず一つの `ending` を付ける。BPや開始家庭から固定せず、成人後まで計算した状態を使い、次の優先順で最初に該当したものを選ぶ。スコアの数式・既存乱数は変えない。しきい値は調整仮値。

| ID    | タイトル                   | 条件                                         | 結末の軸                           |
| ----- | -------------------------- | -------------------------------------------- | ---------------------------------- |
| EN-01 | 立派な額縁、静かな食卓     | 社会的成果>=70かつ親子信頼の平均<40          | 成果の大きさと会話の少なさ         |
| EN-02 | 「あのとき、ごめん」の続き | repairedかつ信頼平均>=60                     | 修復した関係が続く                 |
| EN-03 | それぞれの予定表           | 両親の最期の充実平均>=70かつ社会関係平均>=50 | 親自身の人生も続く                 |
| EN-04 | 遠くの街から、いつもの声   | 遠方かつ信頼平均>=60                         | 距離を越えた関係                   |
| EN-05 | 小さな靴、大きな予定       | 上記以外                                     | 喜びと心残りを含む一つの家族の歩み |

EN-05は低幸福も含むため、幸福や関係を無条件に美化しない。各エンディングに親の点と内訳、子の幸福・主体性、最期までの年表を併記する。平均は床方向の整数除算。AC-009-E：5種類すべてへ通常の合法な選択列で到達でき、優先条件が重なる場合にも分類が一意。実装は[adult.ts](../../src/engine/adult.ts)、到達検証は[公開CLIでの到達確認](../../scripts/public-play.ts)。
