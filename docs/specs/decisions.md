# S-016：年齢・状況に応じた選択中心のゲーム

更新日：2026-09-16。状態：コンセプトの変更方針はユーザー指定・合意済み（D-029）。D-030の実装依頼に基づき、共通エンジン・CLI・ブラウザ画面を実装。以下の設計案は末尾の詳細で具体化して採用した。検証結果は[開発計画](../development-plan.md#選択中心のゲームへの変更2026-09-16)。

本仕様は、S-001・002・004・005・007・009・011・013・015のうち、親の呼称、配分入力、ターン内の判断、イベント提示、家族の概要、終了条件を更新する。旧分冊は現在動いている実装の仕様として残す。新方式の計算式・コンテンツ・保存契約は末尾の実装詳細に定める。Q-018〜020は今回の実装範囲で解決。

## 合意済みの変更

- 親A・親Bの呼称を「父」「母」に変更する。
- 毎ターン、ランダムな特殊イベントを1件提示し、中央のアクション欄で対応を必須選択にする。
- 親のパラメータを直接配分する操作を、子どもの年齢・状況に応じた意思決定へ置き換える。
- 通常の判断テーマは毎ターン固定で3件。それぞれのテーマで選択肢を必ず1つ選ぶ。「何もしない」「現状を維持する」も選択肢にできる。当初の5〜10個案は、この指定で置き換える。
- 選択による成果は親の能力によって変わり、疲労・ストレス・費用も選択に応じて変わる。
- 「家族の様子」は、家族全体の状況を一言で示す約5段階の表示にする。
- 一家離散または離婚が発生するとゲームオーバーになる。

半年・全40ターン、子ども1人、通常完走後の成人期・老後・最期、親子別の幸福評価は維持する。途中終了したプレイを、老後まで完走したプレイと区別する。

## ターンの流れ（採用設計）

特殊イベント1件は通常の3件と別枠と解釈する。1ターンに必須の回答は合計4件。特殊イベント別枠の方針はD-030の実装依頼で採用済み。「固定」は件数であり、毎回同じ題材を出す意味ではない。

1. **特殊イベント**：年齢・家庭状況に適合する候補から1件抽選し、アクション欄に表示する。対応を確定するまで通常の判断へ進めない。別メニューへの移動やEscapeで未回答を飛ばせない。中断・保存は可能とする。
2. **イベントの結果**：対応を一度だけ反映する。ここで離婚・一家離散が成立したら終了し、通常の判断を出さない。
3. **今期の3件の判断**：イベント反映後の年齢・状況・過去の選択から、重複しない3テーマを提示する。各テーマで必ず1つ回答する。入園先のような排他的な選択肢は、同じテーマの中にまとめる。
4. **半年を進める**：3件すべての回答と費用・前提条件を検査し、一括確定する。今期の継続費用、成果、父母それぞれの疲労・ストレス等を更新する。選び直すだけでは費用も時間も消費しない。
5. **振り返り**：選択と結果のつながり、家計、家族の様子を表示する。離婚・一家離散が成立した場合はゲームオーバー。成立しなければ次期へ進み、40期終了時は成人後へ移る。

未回答と「何もしない」を区別し、初期選択や前期の回答の自動引き継ぎで回答済みにしない。入園・習い事などの生活上の継続状態は保持するが、その期の回答は改めて行う。「何もしない」を選んでも既存の通園費や生活費、自然な時間経過は発生する。

候補不足のときも3テーマを出せるよう、年齢に適した日常の判断を用意する。特殊イベントにも日常的な候補を用意し、候補0件で止まらないようにする。単に件数を満たす無関係な質問は増やさない。

## 判断の具体例（採用設計）

3歳のある期の例。特殊イベント「父の仕事が急に忙しくなった」に対応した後、次の3テーマに回答する。

| 判断テーマ | 選択肢の例 |
| --- | --- |
| 入園先をどうする？ | 幼稚園／インターナショナル幼稚園／保育園／もう半年自宅で過ごす |
| 新しい環境にどう慣れる？ | 父が一緒に見学する／母が一緒に見学する／家で話を聞く／今期は特別な準備をしない |
| 家族の疲れにどう対応する？ | 家事支援を頼む／父母が交代で休む／家族で近場に出かける／今の生活を続ける |

題材は年齢で変える。乳児期なら睡眠・預け先・支援、学童期なら放課後・習い事・友人、思春期なら進路・距離感・家庭内の約束などを扱う。上表の分類を全40期に固定しない。これは架空の選択例であり、現実の入園制度や育児上の優劣を示すものではない。

## 親の能力と選択の影響（採用設計）

父母は個別の能力を持つ。呼称変更だけを根拠に性別で得意分野・役割を固定しない。能力候補は「対話」「生活の段取り」「学びの支援」など。採用した項目、初期値、成長、公開範囲は末尾の実装詳細を参照。

各選択肢には、関係する親・能力、成果、費用、父母別の疲労・ストレス、継続期間、子どもや家族関係への影響を定義する。同じ見学でも、担当する親の対話能力や現在の疲労によって得られる安心感と負担が変わる。費用の高さだけで成果を保証しない。

選択前には、確定している費用と継続費用、負担の見込み、成果に関わる得意不得意を表示する。結果には、能力・子どもの状態・偶然がどう関わったかを分かる範囲で説明する。子どもの隠し適性を直接公開しない。

3件を合わせて成立する組み合わせが必ずあるようにする。選択不能には理由を示し、金銭不足や選択同士の競合で行き止まりにしない。具体的な費用計算と無料選択の保証は末尾の実装詳細を参照。

## 家族の様子とゲームオーバー

採用した5段階の名称と順序：

| 段階 | 一言表示 |
| --- | --- |
| 5 | 家族円満 |
| 4 | おだやかな家庭 |
| 3 | すれ違い気味 |
| 2 | 不穏な雰囲気 |
| 1 | 一家離散の危機 |

家族全体の概要として常に1つ表示し、必要なら理由の短文を添える。父母の関係、親子の信頼、疲労・ストレス等との対応、境界値は末尾の実装詳細に定める。

「一家離散の危機」は終了直前の状態であり、到達しただけではゲームオーバーにしない。関係修復や支援で回復できる段階とし、実際の離婚・一家離散が成立した時点でゲームオーバーにする。終了理由・直前の選択・経過を示し、次の育児ターンや通常の老後計算へは進めない。両方が同時成立した場合の表示順、成立条件、成人後への適用範囲は末尾の実装詳細に定める。

これは本作の終了条件であり、現実の離婚や家族の形を一律に評価するものではない。

## 共通処理・保存（採用設計）

特殊イベント待ち／通常3件の回答中／期の結果／ゲームオーバー／通常完走を共通エンジンで区別する。CLIでも未回答のイベントや3件を飛ばせない。UIは同じ公開操作を使う。

抽選結果、提示した3件、イベントの適用済み状態、選択途中の回答を保存する。再読・画面再表示・保存再開で抽選し直さず、再送でイベント効果や半年の更新を二重適用しない。旧保存を黙って新ルールで再計算しない。具体的な版と互換方針は末尾の実装詳細に定める。

## 受け入れ条件（新方式の実装時に検証）

- **AC-016-A**：新方式の画面・CLIの人物表示が父・母で統一され、配分入力を要求しない。
- **AC-016-B**：各育児ターンで特殊イベントを1件だけ提示する。未回答では先に進めず、中断・再開でも同じイベントが出て、確定効果は一度だけ適用される。
- **AC-016-C**：イベント対応後、継続可能なら通常の判断がちょうど3件出る。0〜2件の回答では確定できず、各1件の有効な回答でのみ進行する。「何もしない」は回答として数え、未回答とは区別する。
- **AC-016-D**：年齢・状況・継続状態に応じて題材が変わり、候補不足・金銭不足・選択の競合でも合法な回答の組み合わせがある。年代境界を含む全40期で確認する。
- **AC-016-E**：同じ選択・子どもの状態・乱数条件で関連する親の能力だけを変え、定義した成果差を確認する。父母別の疲労・ストレス、即時・継続費用が仕様どおりに反映される。
- **AC-016-F**：家族の様子は5段階のうち1つになり、各境界と回復経路を確認する。危機の表示だけでは終了しない。
- **AC-016-G**：離婚・一家離散の各成立ケースでゲームオーバーとなり、その後のターンや通常の老後処理を実行しない。40期目の終了判定でも通常完走より優先する。
- **AC-016-H**：イベント対応前後、通常の回答途中、ゲームオーバーからの保存再開と操作再生で結果が一致する。CLIとUIが同じルール・公開情報を使う。
- **AC-016-I**：ゲームオーバーにならない経路は、0〜20歳の40期、成人後、父母の最期、親子別評価まで到達する。

受け入れ条件の機械検証は[境界・保存・完走テスト](../../tests/decisions.test.ts)、公開操作の確認は[CLIプレイ](../../scripts/public-play.ts)と[ブラウザ検証](../../scripts/browser-check.ts)。人による面白さ・バランスの評価は未実施。

## 実装対象の詳細（2026-09-16、D-030）

以下を今回の採用設計とし、上記の設計案を具体化する。値はゲーム調整用の仮値。

- 新規ゲームはrules-3 / data-3 / save-4。旧save-2・save-3は変換せず旧ルールで再開する。新設定は本編JSONのdecision_gameに定義し、保存へ固定する。
- 能力は父母それぞれ「対話」「段取り」「学びの支援」（0〜100）。初期値はシードから各40〜70で独立抽選し、性別で差を固定しない。疲労も父母別に0〜100で持つ。
- 能力に関係する選択の成果は、設定の基本成果に「能力÷25の整数部」を加算し、疲労70以上なら2減算（最低0）。担当者の疲労増分は設定値から段取り÷30の整数部を差し引く（最低0）。段取りを使う選択では能力由来の成果分を追加の疲労回復に使う。子どもの興味60以上の分野は能力成長+1、新しい有料の通園・活動では慣れ方の個人差×2の負担が加わる。親の能力自体は今版では固定。
- 特殊イベントの選択は即時確定・保存し、再選択不可。3件の判断は半年を進めるまで選び直せる。通常の3テーマは年齢別の生活判断、子どもとの関わり、家族の生活・回復から各1件。状況が悪いときは関係修復のテーマを優先する。
- 抽選はシード・期・用途ごとに固定する。特殊イベントは年齢・条件が合う候補から毎期1件。通常判断の候補にも条件と年齢範囲を持たせ、全40期で各枠の候補と費用0の選択を検査する。追加パックの既存イベント・行動も利用条件を満たす場合に候補へ取り込む。
- 半年の基礎収入は父母の通常勤務収入の合計、生活費は難易度と年代の設定値。入園先等の継続契約は同じ枠の選択で置換する。費用は即時支出＋選択後の継続費用とし、全件を合算して予測する。支出超過は確定前に拒否する。通常判断は回答途中に一時的な超過を許し、他の選択を変更して解消できる。無料の現状維持／継続契約を解除する選択を常に用意する。
- 半年の自然変化は疲労+4、ストレス+2、夫婦関係−2、親子信頼−1、学齢期の子どもの学習・創作能力+1。親の疲労70以上では追加ストレス+2。各選択の効果を加え、0〜100に収める。
- 家族の状態値は夫婦関係と父母への信頼の平均から、父母のストレス・疲労の平均の20%を差し引いた値。70以上＝家族円満、50以上＝おだやかな家庭、30以上＝すれ違い気味、15以上＝不穏な雰囲気、それ未満＝一家離散の危機。
- 半年確定後、夫婦関係10以下かつ父母の平均ストレス75以上が2期連続なら離婚。夫婦関係20以下かつ父母への信頼がともに15以下が2期連続なら一家離散。同時成立は一家離散を優先。条件から外れた期に連続数をリセットする。悪化の予兆と無料の修復選択を表示する。
- 危機の特殊イベントに、離婚・一家離散を明示的に確定する選択と、無料で修復する選択を用意する。前者は明示選択した場合だけ即終了する。通常のランダムイベントだけでは突然終了しない。
- 終了判定は育児中に適用し、40期目も老後への移行より優先。成人後には新たな離婚・一家離散判定を加えず、既存の自動進行・評価を維持する。
- 特殊イベントの確定も操作再生へ記録する。回答途中と終了状態を保存でき、再送・再開で効果が重複しない。ゲームオーバーは専用の理由・履歴を返し、通常の幸福評価は生成しない。

## 10点スケールと選択の強化（2026-09-17、D-032）

新規ゲームはrules-4 / data-4 / save-5。父母の健康・ストレス・充実・社会関係・後悔・疲労・能力、夫婦関係、祖父母の体力・関係を0〜10の整数にする。初期値は旧値÷10を四捨五入。年齢・金額・子どもの内部状態・最終幸福評価（100点）は単位を維持する。旧保存は旧版を保持する。

選択の親・夫婦・祖父母への非ゼロ効果は、旧設定の絶対値÷5を切り上げて符号を戻す（例：+6→+2、−12→−3）。子どもへの選択効果は2倍。能力は10倍して既存の成果式へ接続し、親の疲労増加は段取り÷6の整数部で軽減し、最低1点。段取りによる追加回復は能力込みの旧成果÷5を切り上げる。自然変化は旧設定÷10を符号付き切り上げ、疲労+1・ストレス+1・夫婦関係−1を基本とする。子どもの信頼の自然減少は従来どおり。判定は親の値を100点相当へ換算して既存境界を使う。成人後は100点相当に接続して従来の寿命・評価計算を行い、親の最終状態と結果の健康は10点へ戻す。

- **AC-016-J**：新規保存・CLI・画面の対象値が整数0〜10、メーター上限10となる。選択1件で非ゼロ効果が消えず、上下限で止まる。
- **AC-016-K**：能力差・危機からの回復・途中終了・40期と成人後・保存再開・再生一致を新旧両版で確認する。面白さ・難易度はQ-014の人による評価対象とする。

実装・検証：[開発計画の記録](../development-plan.md#10点スケールと選択効果の強化2026-09-17)。

## 家計の選択を強める（2026-09-17、D-033）

新規ゲームはrules-5 / data-5 / save-6。10点スケールは維持する。既存保存は設定と旧ルールをそのまま保持し、再計算しない。

本編の単発有料選択は従来の4倍（支援5→20万円、訪問支援6→24万円、家事支援8→32万円）、通園・習い事の継続費は2倍（12→24万円、24→48万円）にする。基本収入・生活費・初期資金は維持し、選択による家計差を大きくする。金額の正本はconfig/base.json。追加パックの費用は作者の設定を維持する。

家族の生活・回復の判断では、父または母が追加の仕事を引き受け、半年確定時に40万円を得る選択を用意する。担当者の疲労+2・ストレス+2、夫婦関係−1が基本負担。繁忙期には父または母が臨時の仕事を引き受けて即時60万円、地域の集まりでは父母で不用品を販売して即時40万円を得る選択も用意する。収入額は固定し、抽選・保存再開で変えない。無料の休息・修復・継続契約解除は残す。

選択肢のincomeは省略時0。特殊イベントは現在資金から費用を支払えるときのみ選択可能で、支出・入金を一度だけ反映。通常判断の収入は半年の基本収入へ加算し、費用・選択後の継続費とともに予測する。選び直しや再表示では入金しない。半年の不足判定では選択による収入も利用可能とする。保有上限99999万円と計上外の記録を維持する。

選択前に支出と入金額、入金時点、確認画面に半年の収支と残金を表示する。イベント結果・半年履歴に資金の変更前後と差分を記録する。

- **AC-016-L**：有料選択・継続費・収入選択が予測と実際の資金に一致し、選び直し・再送・保存再開で二重入金しない。資金不足は確定前に拒否し、無料で継続可能。
- **AC-016-M**：40期・成人後と旧保存の再生を維持し、同じ期で回復への支出と追加収入による資金差を確認する。

## 自動イベント（2026-09-17、D-034）

新規ゲームはrules-6 / data-6 / save-7。本節は従来の特殊イベント1件・回答必須の規則とAC-016-B/C/Hを更新する。各育児期の開始時、子どもの月齢（完了期数×6）と家族の状態を使って各イベントを独立に抽選する。件数の上限・最低件数は設けず、同一イベントは1期に1回。発生時に効果を自動適用する。UIでは結果を判断とは別の単独カードに表示し、「3つの判断へ」で通常判断に移る（2026-09-17の表示修正）。このボタンは画面遷移のみで、イベントの選択や効果確定は行わない。イベントが0件なら直接3判断を表示する。進行ナビの「出来事」はクリックで今期の結果を再表示できる。0件の場合は発生なしの案内を出す。判断・確認へ戻っても回答と資金は保持し、効果を再適用しない。成人後の進行は維持する。

専用のconfig/events.jsonを新規設定へ合成し、保存内へ固定する。各定義はID、本文、good/bad、月齢の上下限（両端含む）、基本確率0〜100%、全条件、条件付き確率補正、再発間隔（期）、一度限り指定、数値効果を持つ。条件は子どもの能力・興味・信頼・負担・主体性、父母それぞれの状態・能力・疲労・年齢、夫婦関係、祖父母の体力・関係・資金・家計を参照できる。親等は現行の10点、子どもは内部100点、金額は万円、年齢は月で指定。

全イベントの条件と確率補正は期首の同じ状態で判定し、確率を0〜100に収め、ID順でシード・期・イベントIDを用途とする抽選を行う。該当する全件をID順に適用する。数値効果は直接加算し各パラメータの上下限で止める。支出はその時点の所持金まで（借金は作らない）。収支の実額と上限超過を履歴へ記録し、子どもの内部数値は公開せず観察に反映する。新規ルールの祖父母の初期援助資金はdecision_game.initial_grandparent_fundsで定義（本編100万円、省略時40万円）。祖父母の援助は資金50万円以上を条件とし、家計+50・祖父母資金−50。選択式の旧本編・旧追加パックイベントはrules-6では発生させず、追加パックの通常行動は維持する。

再読・再開・再送で再抽選・二重適用しない。旧保存は元のルールで再生する。UIとCLIは発生した全件の結果を表示し、発生なしでも3判断へ進める。

- **AC-016-N**：0件・複数件、年齢境界、状態条件・確率補正、善悪の効果、再発間隔・一度限り、上下限を検証する。
- **AC-016-O**：同じシード・設定・操作で再現し、保存再開・再送・再生で一度だけ適用。通常判断3件と40期・成人後を維持する。旧版の検証も維持する。

## 祖父・祖母の個別化（2026-09-17、D-035）

新規ゲームはrules-7 / data-7 / save-8。祖父・祖母はそれぞれ体力・関係（整数0〜10）、援助資金（整数0〜99999万円）、地域のつながりを持つ。初期値は設定のdecision_game.initial_grandparentsを正本とし、両者とも体力8・関係6・資金50万円・つながりあり。性別による能力差は設けない。公開JSONのgrandparents.members.grandfather / grandmotherをCLI・画面で共有する。旧互換のgrandparents直下は体力・関係の平均（四捨五入）、資金合計、つながりの論理和とする。

援助は各人の資金50万円以上が条件で、本人から家計へ50万円を移す。各人の発生率6%、関係7以上で+5%、再発間隔8期。合計資金100万円と基本発生件数の期待値を維持する。体調不良は各人5%・体力5未満で+20%、費用10万円・本人の体力−1、間隔6期。両者が同じ状態なら旧版と期待費用が等しい。体力8未満の本人には10%・間隔4期で体力+1の回復イベントを設ける。抽選は独立であり発生時期や同時発生率まで旧版と同一ではない。これらはゲーム調整値で、現実の育児・健康に関する主張ではない。

旧保存は共通値・設定・ルールを維持して変換しない。旧追加行動のGMは合計額を二人へ均等配分（端数は祖父、不足分は他方）、GRは両者へ適用する。新規自動イベントの効果は個人パスを使用し、旧共通パスの効果も同じ配分規則で互換処理する。

- AC-016-P：一方の援助・体調・関係の変化が他方を変更せず、UI・CLI・履歴に対象者が明示される。二人の資金は独立して減り、合計援助は初期100万円まで。
- AC-016-Q：上下限、回復、保存・再開・再生、40期から成人後までを検証する。旧保存の共通値と再生結果を保持する。
