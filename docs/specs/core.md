## S-001：時間軸と操作対象

子どもは架空年Y0の4月2日生まれ。開始日も同日、月齢0。第tターン（1〜40）の開始月齢は `6*(t-1)`、完了月齢は `6*t`。奇数ターンは春〜夏、偶数は秋〜冬。日付は季節・学年表示用で、日次計算はしない。年齢は開始月齢を12で割った商と余り。学年は開始年齢で判定する。

| 開始年齢 | ターン | stage     | 世話の必要時間 D | 半年の子ども生活費 | 学年表示              |
| -------- | ------ | --------- | ---------------: | -----------------: | --------------------- |
| 0〜2歳   | 1〜6   | baby      |                6 |                 20 | 未就学                |
| 3〜5歳   | 7〜12  | preschool |                4 |                 24 | 未就学                |
| 6〜11歳  | 13〜24 | primary   |                2 |                 28 | 小1〜小6：年齢−5      |
| 12〜14歳 | 25〜30 | junior    |                1 |                 32 | 中1〜中3：年齢−11     |
| 15〜17歳 | 31〜36 | senior    |                1 |                 36 | 高1〜高3相当：年齢−14 |
| 18〜19歳 | 37〜40 | launch    |                1 |                 36 | 進路準備期            |

学年はイベントを読むためのラベルで、入学試験や就学義務の再現ではない。40回目の更新後、子ども20歳、親A・Bとも50歳。第41ターンを作らず、[S-009](ending.md)を同じ確定操作の中で自動計算して `finished` にする。自動進行中にユーザー入力を求めない。

プレイヤーは親A・Bの仕事、世話、関わり、休息、自分の時間と、家庭の活動方針・支援利用を決める。性別による能力差はない。子どもの本心、進路の最終決定、成人後の連絡・居住、祖父母の利用可能条件は直接操作しない。

## S-004：行動と入力

毎期の編集案 `plan` は以下の全項目を持つ。部分変更はこの編集案にマージする。どの項目も、変更した時点では支出・能力変化を起こさない。確定時に一度だけ適用。既存の案を何度でも変更でき、`reset-plan` で前期確定案へ戻せる。初回の前期案は下の初期案。年代や支援条件の変化で使えなくなった継続設定は自動消去せず、理由と修正案を表示する。

| 入力パス            | 値・条件                 | 時間・金銭・式で使う値                                         |
| ------------------- | ------------------------ | -------------------------------------------------------------- |
| parents.p.work      | reduced / normal / heavy | 下表                                                           |
| parents.p.care      | 0〜6                     | 親の時間を値だけ消費                                           |
| parents.p.bond, b_p | 0〜2                     | 会話・遊び・同席。時間を値だけ消費                             |
| parents.p.rest, r_p | 0〜3                     | 休息。時間を値だけ消費                                         |
| parents.p.self, j_p | 0〜2                     | 仕事外の趣味・友人。時間を値だけ、費用4×値                     |
| activity.domain, d  | none / study / craft     | babyはnoneのみ。無料の遊びはbondに含む                         |
| activity.level, l   | noneなら0、それ以外1 / 2 | 活動費0 / 12 / 30万円、スポンサーの時間0 / 1 / 2               |
| activity.sponsor    | A / B                    | 費用は家計。時間と親の負担は指定親に計上。noneでも保持         |
| style, q            | respect / coach / push   | 式中の圧力は0 / 1 / 2。babyでは実効q=0                         |
| help                | none / grand / paid      | grand:条件GH>=40かつGR>=30、無料で世話2。paid:費用8万円で世話2 |

| work    | 半年収入 Y_p（万円） | 時間 w_p | 負担 e_p | 仕事による充実 f_p |
| ------- | -------------------: | -------: | -------: | -----------------: |
| reduced |                   90 |        2 |        2 |                  1 |
| normal  |                  130 |        4 |        4 |                  3 |
| heavy   |                  180 |        6 |        7 |                  4 |

時間は半年の配分を表すゲーム内12単位／親で、実時間ではない。各親について `w+care+b+r+j+スポンサー活動時間 <=12`。余りは予備時間として表示し、勝手に休息に換算しない。世話は `care_A+care_B=max(0,D-支援2)` を満たす必要がある。支援の余分は他の自由時間には変換しない。

初期案：両親normal、care各3、bond各1、rest各2、self各0、activity none/0/A、style respect、help none。初回は各10単位、収入260、費用220、差引+40。毎期同じ案を維持するときも入力・確定条件は同じ。

費用 `cost=200+年代の生活費+活動費+8*[paid]+4*(j_A+j_B)+イベント選択の費用`。既知のイベント援助金は収入に加算する。`M+Y_A+Y_B+既知の援助金-cost>=0` が必要。借入・破産・失職は初版に入れない。無料のイベント選択と、normal/none/helpなし、世話を半分ずつ、bond/rest/self=0の修正案なら全期で確定可能。健康低下で就労選択を禁止しないが、老後への健康の影響は残る。残金が99999を超える部分は「保有上限による計上外」と履歴に明記する。

入力型・範囲の違反は即時エラー。時間・費用・支援条件の不足は編集案を保持し、`can_advance=false` と公開理由を出す。これにより複数項目を順に直せる。確定の失敗では状態・乱数・リビジョンを変えない。選択不能理由に子どもの真値は使わない。

## S-001：ターン処理順

1. 開始時の確定状態から観察と出来事を生成して保存する。newではt=1、advance後では次のt。各出来事の発生条件はこの開始状態だけを見る。今期案の変更で抽選をやり直さない。
2. observe/actions/forecastで確認し、planと出来事の回答を編集する。原子的な確定前に全回答、時間、費用、支援条件を検査。
3. advance成功時、今期の既知の収入・費用を一括決済。予約の追加・祖父母からの送金は選んだ選択肢分だけ記録。
4. 通常更新を下記の式で計算する。すべて今期開始値を参照し、差分は同時適用する。
5. 出来事の非金銭の即時効果をイベントID順に適用。遅延効果の予約を追加。続いて `due_turn=t` の既存予約を元ターン・イベントID順に適用して削除。金銭効果は3で処理済みなので二重適用しない。
6. [S-005](events.md)の珍事を1件まで処理。通常更新とイベントを反映した最終状態を得る。
7. 月齢・完了ターン数を更新し、今期の選択・公開結果・内部差分・予約消化を記録。直近2期のX差分を更新し、今期案を前期案として保存。
8. t<40なら次期を開く。t=40なら[S-009](ending.md)を計算し、finishedにする。全工程を一つの保存トランザクションとし、部分成功はない。

## S-002・S-003・S-006：通常更新式

以下の右辺は開始時の状態。`active` はd!=none、`changed` はactiveかつdが前期domainと違うこと。レベル変更だけではchangedにしない。`a_p=l` はスポンサーのみ、それ以外0。`Z=[S_A>=70 or S_B>=70]`。`conflict=[X>=60 or (active and I_d<40)]`。実効圧力をqとする。

```text
S_p' = C(S_p + e_p + care_p + a_p - 3*r_p - 2*j_p - 3)
H_p' = H(H_p + [r_p>=2] - 2*[S_p>=70] - [S_p>=90])
F_p' = C(F_p + f_p + 3*j_p - 4 - 2*[S_p>=70])
N_p' = C(N_p + 3*j_p - 2)
T_p' = C(T_p + b_p - 1 + [q=0] - 2*[q=2 and conflict])
G_p' = C(G_p + [S_p>=70 or T_p<30 or F_p<25]
             - [b_p>=1 and S_p<60 and T_p>=50])
K' = C(K + [r_A>=1 and r_B>=1] - [abs(care_A-care_B)>=3] - Z)
X' = C(X + 2*l + 2*q + V*[changed] + 2*Z - b_A-b_B - 3*[not active])
U' = C(U + [stage!=baby]*(2*[q=0]+[q=1]-2*[q=2]))
```

各分野について、`base=1` はprimary/junior/senior、それ以外0。

```text
gain_d = max(0, base + [dが活動分野]*(l+[I_d>=60]+[A_d=3 and tが偶数]) - 2*[X>=70])
B_d' = C(B_d + gain_d)
I_d' = C(I_d + [dが活動分野]*(1-3*[X>=60]) - [tが偶数 and active and dが非活動分野])
GH' = min(80,max(0,GH + ( -3 if help=grand else 1 ) - [tが偶数]))
GR' = C(GR + ( -1 if help=grand else 1 ))
```

GM・GNは通常更新では変わらない。新しい場の負担は活動開始時のみだが、蓄積したXは休止や関わりで減らす必要がある。q=2も、低疲労かつ興味がある間は関係への追加罰を受けない。数値だけを上げる方針がどの家庭でも最善という保証はしない。成人後の評価を直接書き換える通常行動はない。

## S-003：公開観察

毎期開始と結果表示で、現在の状態から以下を生成する。同じ時点の再読では文も変わらない。結果と次期開始が同じ状態なら共通の観察を使う。誤った情報を混ぜる抽選は初版ではしない。複数の内部状態が同じ文に対応する粗い観察で不確実性を作る。

| observation.code     | 生成条件とtext                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| energy               | X<40「余裕がありそう」／40〜69「少し疲れている様子」／70〜100「休みたがることが増えた」                |
| relationship.A/B     | T_p<30「話しかけても会話が続きにくい」／30〜59「用事や近況を話す」／60以上「自分から話をしに来る」     |
| agency               | U<30「決めてもらうのを待つことが多い」／30〜59「選択肢を示すと選ぶ」／60以上「自分の希望を言う」       |
| interest.study/craft | I_d<40「最近は話題にしない」／40〜59「誘うと取り組むことがある」／60以上「自分から話題にする」         |
| progress.study/craft | B_d<30「試しながら覚えている」／30〜59「一人でできることが増えた」／60以上「得意なこととして披露する」 |
| settling             | 前期domain変更があり直近差分X>=5なら「新しい場の後は疲れている様子」。原因を気質と断言しない           |
| recovery             | 前期にrepair選択か活動休止があり直近X差分<0なら「前より余裕が出てきた様子」                            |

babyのagencyは非表示、relationshipは同じ区分で「反応が少ない／声や気配に反応する／自分から触れ合いを求める」に置換。interest/progressは数値区分を保ち「学習=ことばや数の遊び、創作=形や音の遊び」と表示。0歳の発言を捏造しない。

bond合計>=2だった前期の次期観察では、直近2期のX差分が両方正なら `trend: strain_rising`「疲れが続いて増えている様子」、両方負なら `strain_easing`「疲れが続いて和らいでいる様子」、それ以外なら `mixed`「調子には波がある」を追加。履歴が2期未満ならtrendなし。これが関わりによる追加の手がかりで、適性の数値鑑定はしない。

## 受け入れ条件

- AC-001：40回で月齢240。0/6/12/24/30/36/40完了後の次期・終了が年代表に一致し、1〜40が各一度。
- AC-002：初期案の初回はM=160、S各28、H各81、F各49、N各48、K=61、T各61、X=15、U=40、B各10、I=(40,65)、GH=80、GR=61、G各9（E-01:watch、珍事なしの内部fixtureで確認）。
- AC-003：13時間の案や支援条件未達は確定不可。無料案へ変更して継続できる。引き継ぎ設定と取消で費用が増えない。
- AC-004：全子ども真値を変えても、通常JSONに真値のキー・閾値・適性は出ない。energyの各境界39/40/69/70とbondによるtrendを照合する。
- AC-006：高疲労でactivity none、respect、bond各1を選び、親が高疲労ならXは毎期少なくとも3減る。修復の関係増加と遅延効果が[S-005](events.md)どおり一度発生する。育児中のH=10・X=100でも終了を強制せず、選択を続けられる。
