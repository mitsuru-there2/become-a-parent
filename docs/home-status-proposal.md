# ホームと家族ステータスの改善案

2026-09-21。状態：**採用した原案**。後続のユーザー依頼でD-072として採用・実装。現行仕様は[S-003](specs/core.md#観察のビジュアル表示2026-09-21d-072)・[S-018](specs/selection-tree.md#ホームと家族4枠2026-09-21d-072)を参照する。以下は検討時の原案であり、細部の差異は現行SPECを優先する。

対象：[S-003](specs/core.md#s-003公開観察)、[S-018](specs/selection-tree.md)、D-058。未決事項：Q-023。ゲーム内の情報設計を扱い、現実の子どもの発達を評価するモデルにはしない。

## 目的と現状

ホームを「家族の今をつかんで、次の選択へ進む場所」にする。家族は下部の子ども・父・母・実家の4枠に統一し、全枠をタップ可能にする。ホームでは様子の変化と負担、詳細では成長・興味・関係とその手がかりを確認する。

現行コードとブラウザ画面を確認した。子どもは上部の観察文、父母・実家は下部に分かれている。PCでは父母それぞれ9項目が常時表示される。子どもは信頼2値、ストレス、自律性、興味2値、能力2値、適性2値、適応負担の11値を持つ。専用の健康・体力や、育児中の幸福メーターはない。成績は学び能力の数値を公開する既存の例外で、ほかの内面は主に3区分の観察として伝えている。

根拠：[型](../src/engine/types.ts)、[観察生成](../src/engine/simulation.ts)、[子ども表示](../src/components/game/child_status.tsx)、[家族表示](../src/components/game/party_status.tsx)。

## パラメータの整理案

「公開する事実」「様子だけ見える内面」「真値を隠す個人差」の3種類を区別する。詳細を開いても、隠している真値は表示しない。

| 項目 | ホーム下部の子ども枠 | 子ども詳細 | 内部値の扱い |
| --- | --- | --- | --- |
| 年齢・所属 | 年齢を表示。所属は上部に維持 | 現在の学校・ルート | 事実として公開 |
| ストレス／疲れ | 「余裕」として3種の表情・記号 | 3状態の図と観察文、公開済みの回復・負担の兆候 | 真値は非公開。健康や幸福と混同しない |
| 父との信頼・母との信頼 | 父・母を識別できる小さな関係アイコンを各1つ | 親子の肖像を結ぶ図。各関係の観察を併記 | 各3状態。2人を平均しない |
| 学び・創作への興味 | 最近の変化があるときだけ印 | 本・工作などのアイコンと3状態。「好き」と「得意」を別行にする | 真値は非公開。低い興味を赤い警告にしない |
| 学びの能力／成績 | 常時表示しない。進路条件にはその場で表示 | バー＋現在値と必要値。学齢前は「学びの育ち」と観察中心に表示 | 既存の公開数値を維持。隠し適性とは別 |
| 創作の能力 | 常時表示しない | 成長段階の図と、できるようになったこと | 初版は既存の3区分を使い、真値の新規公開をしない |
| 自律性 | 常時表示しない | 「自分で選ぶ様子」として行動の図と観察 | 真値は非公開。乳児期は非表示を維持 |
| 学び・創作の適性 | 表示しない | 才能ランクや鑑定結果を作らない | 隠しパラメータを維持 |
| 新しい場への適応負担 | 表示しない | 発生したときに「新しい場のあとで疲れている」などを表示 | 固定値は非公開。性格・能力の優劣として扱わない |

まずは既存パラメータの役割と表示を整理する。ストレスの裏返しである「余裕」を別の保存パラメータとして追加しない。子どもの総合点や常時の幸福ゲージも追加しない。

将来は、現在の学び・創作だけでは運動や友人関係の選択結果を表しにくい点を見直す候補とする。「からだを動かす」「人と関わる」を加えた4分野は検討できるが、それぞれの興味・経験、影響する選択、出来事、成人後への接続を設計してから追加する。既存値を転用した架空の運動能力・社交性メーターは作らない。

## ホームの構成

```text
┌──────────────────────────────────────┐
│ 8歳・春夏／小学生    家族の様子    資金 │
├──────────────────────────────────────┤
│                 ホーム               │
│       教育・進路        遊び・放課後  │
│                 家庭生活             │
│       実家との関わり    仕事・家計    │
│       今期、対応が必要なこと          │
├─────────┬─────────┬─────────┬────────┤
│ 子ども  │ 父      │ 母      │ 実家   │
│ 肖像    │ 肖像    │ 肖像    │ 家の絵 │
│ 余裕    │ 健康    │ 健康    │ 体力   │
│ 父・母  │ 疲労    │ 疲労    │ 関係   │
│との関係 │ストレス │ストレス │援助資金│
├─────────┴─────────┴─────────┴────────┤
│ ホーム   暮らし   記録   …   半年進行 │
└──────────────────────────────────────┘
```

画面名・ナビ・戻る操作・案内文・読み上げ名を「ホーム」に統一する。中央の地図表現と5分類への入口は活かせる。下部の「実家」は状態詳細を開き、中央は選択を開くため、中央を「実家との関わり」と呼び分ける。

上部の子ども専用帯を下部へ移し、PCでも家族は要約に統一する。父母の充実感・交流・後悔・対話・段取り・学びの支援は詳細に置く。実家の地域のつながりも詳細へ置く。家族全体の状態と夫婦関係は上部の家族表示から開く。

4枠は分類ツリー閲覧中にも維持し、詳細を閉じると元の分類・スクロール位置に戻る。モバイルは4列を基本とし、肖像＋短いラベル＋小さな状態記号に絞る。操作の高さ44px以上を確保する。文字拡大や極端に狭い画面では2×2を許し、家族の一部を横スクロールの先へ隠さない。半年進行は家族枠と離した専用行に置く。低い画面では中央のみスクロールさせる構成を試す。

既存「家族」画面にある現在の暮らし・取得効果は、新しい「暮らし」画面へまとめる。家族個人のステータスの重複表示を整理しても、取得効果と夫婦関係への導線は残す。

## ビジュアルと詳細のルール

子どもの内面には、連続する精密なバーより3状態の表情・姿勢・関係の図を使う。既存観察が3区分なら3区分のまま図にする。全項目を5段階化する場合は、観察精度の仕様変更として別途判断する。

親の健康・疲労・ストレスは公開されている10点スケールを使った短いバーにする。数値は詳細で確認でき、資金のような判断に必要な事実は数字も残す。疲労・ストレスは高いほど負担が大きいことをラベルと形でも伝える。

子ども詳細は「今の様子」「興味と成長」「父母との関係」「最近の変化」の順。PCでは右側パネル、モバイルでは下から開くシートを提案する。どちらも背景操作を止め、閉じるボタン・Escape・フォーカス復帰を備える。

観察文は図の意味と理由を補うために残す。色だけで判別させず、短い日本語ラベル、形、読み上げ用の説明を併用する。レーダーチャートや全項目共通の赤〜緑評価は採用しない。興味・性格・親子関係を「全部最大なら正解」と見せないため。

変化の印や矢印は、公開区分の変化または既存の公開トレンドがある場合に限る。同じ区分内の隠し数値差分から、増減や精密な履歴グラフを新たに作らない。区分の変化と、既存の関わりで得られる継続トレンドは区別する。選択効果の説明は、実際に起きた気持ちの変化を断定する表示に流用しない。

## 実装順と確認案

1. S-003・S-018で公開項目、区分、年齢別表示、4枠の配置、名称と受け入れ条件を具体化する。採用理由をDに残す。
2. 共通エンジンで公開観察に機械可読の状態IDを追加する。UIが日本語本文を解析したり隠し値を読んだりせず、CLIも同じ状態IDと説明を返す。
3. CLIで観察の境界、情報の公開範囲、年齢別表示、取得後・半年進行後・保存再開の更新を確認する。
4. ホームへの名称変更、4枠、図による状態表示、詳細パネルを実装する。ゲームの進行・保存形式・全40期と成人後の接続を維持する。
5. 320pxの狭い画面・横向き・PC・文字拡大で全枠の操作、重なり、フォーカス、分類への復帰を確認する。公開数値のバーや読み上げ、選択条件にも非公開値が漏れないことを確認する。
6. 人のプレイで「ホームだけで誰に負担があるか分かるか」「好きと得意を区別できるか」「詳細を毎期全員開かなくても判断できるか」を評価する。

採用後の実装・検証結果は[開発計画](development-plan.md#ホームと家族の状態表示2026-09-21d-072)に記録する。人による使いやすさの評価と能力分野の追加は後続。
