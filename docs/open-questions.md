# 未決事項

作成日：2026-09-12。更新日：2026-09-13。

初版に必要だったQ-001〜008・Q-011・Q-013は、合意またはユーザーの委任に基づく設計によって仕様化した。個々の値をユーザーがレビュー済みという意味ではない。未決のままの実装必須ルールと、実装後に確認する調整仮説を分ける。策定状況は[仕様策定計画](specification-plan.md)、規則は[SPEC](SPEC.md)。

## Q-009：複数の子どもと育児編の終了

- 状態：未決・P-EXPAND対象。初版の前提ではない。
- 論点：人数、年齢差、兄弟姉妹の関係、資源共有、終了条件。「末子20歳で終了」は引き続き候補。
- 決める時期：複数の子どもの実装前。専用の追加SPECを作る。

## Q-010：深刻な出来事と表現範囲

- 状態：未決・追加コンテンツ対象。初版は[イベント表](specs/events.md)の題材と[S-009](specs/ending.md)の老後を扱う。
- 論点：非行、虐待、犯罪、失踪などの採否と表現。育児中の即ゲームオーバーや、共働きから直接深刻な結末を発火させる設計は採用しない。
- 決める時期：該当コンテンツ制作前。初版の完了条件をここへ移さない。

- 解決先：[S-010](specs/verification.md)、[接続](specs/events.md)、[通し計算](specs/desk-check.md)。固定の結末にはしない。

## Q-012：ビジュアル化の範囲

- 状態：方向は合意済み（D-009）、具体化は未決・P-VISUAL対象。
- 論点：ドット絵、画面、解像度、書体、動き、操作量、対応環境。CLIと同じ結果・公開情報を使う。
- 決める時期：P-VISUAL開始前。今回の依頼はPoC向けSPECの完成までで、画面や素材の制作には進まない。

## Q-014：初版のバランス仮説

- 状態：未検証の調整仮説。実装必須の処理を未定義にしている項目ではない。
- 根拠：[机上確認](specs/desk-check.md)。内部計算では、支援的な方針の上限到達、立て直し方針の優位、継続した高負担による早い最期、個人差の終盤差の小ささが見られた。
- 決める時期：一括レビューで価値観・表現を確認し、P-TEXTの計算比較・通常AIプレイ・人の確認後に調整。
- 検証方法：[S-012](specs/verification.md)の実行数・観察項目を使う。成功と幸福が両立する例、遠方で信頼が続く例、支援・休止の負担も比較する。
- 見直す条件：能力等が早く上限に達して判断差が消える／一つの方針が比較した全条件で優位／疲労の兆候に対応する意味が薄い／偶然が小さすぎるか判断を無意味にする／人が結果を過度に教訓的・重いと感じる。
- 対応先：該当するcore/events/endingの係数・式・文を変更し、data/rules版、理由、机上結果と影響する受け入れケースを同時更新する。最初から面白さ検証済みとは扱わない。
